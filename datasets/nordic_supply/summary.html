Case 1

Self-service dashboard

"Which orders shipped after the promised date last month, by customer" … then "same thing as a chart, by week".AI business-case demos, case 1 example
  • 14 months of shipments, so "last month, by week" has an answer.
  • The example query returns 347 late orders from 298 customers for August 2026.
  • A story behind the numbers: a Göteborg warehouse outage in the second full week of August, and one carrier, Baltic Freight Line, with transit delays since.
  • 34 claims open for more than 7 days; 185 order lines on backorder across 13 categories.
  • Beyond shipments: 687 credit notes by reason, 294 return authorisations with inspection outcomes, and a 77,000-row stock ledger that reconciles to inventory, so money and stock questions have answers too.
  • Two saved widgets with plain-English descriptions and their SQL, the shape the app stores.

Case 2

Message to claim

"The second pallet from Tuesday's delivery arrived damaged, we need replacements before Friday."AI business-case demos, case 2 example
  • Six customer messages as files: four e-mails, one portal message, one forwarded accounts-payable thread. Two are not in English-only prose: one Swedish, one with a quoted order confirmation.
  • Every message points at real records and none has a claim yet, so the demo creates it.
  • Each detail is cross-checked with SQL: weekdays, pallet contents, quantities, colours, promised vs delivered dates, the carrier's delay event, prices and credit arithmetic.
  • Seven claim types decide which form sections apply; 2,283 active customers and 3,060 active products make the lookups non-trivial.
  • Personal data where real data has it: contacts (a hidden table), a private mobile number in one e-mail, names and phones in some order notes, all tagged in pii-columns.json. Employees reach the model only as a staff view: name and role, never e-mail.
  • An optional messy-data pass (one config overlay) roughens customer names, phone formats and notes and adds duplicate customer records, for the fuzzy-lookup and form-correction demos. Anchors stay clean.

Case 3

Supervised bulk change

"Raise prices 4% on everything from this supplier from the first of next month, except products already on promotion."AI business-case demos, case 3 example
  • Supplier Skarvind AS has exactly 240 active products in three categories, as the document says.
  • Price history with validity ranges: one current row per product, no gaps, no overlaps, nothing already scheduled for October for this supplier.
  • "Already on promotion" has two defensible readings, and the data makes them differ by one product, so the model has to say which it used.
  • 25 other suppliers' products already carry a price starting on 1 October, so the pattern the AI must write exists in the data.
  • Empty bulk_change_batches and bulk_change_items tables ship in the DDL for the proposal and approval flow, next to the shared activity_log.

What the model sees

Exposure is decided in the data, not in the app

  • 20 of 23 tables are exposed to the AI. users, customer_contacts and saved_widgets are not; employees appear through the staff view.
  • A read-only database account, ai_reader, with SELECT on exposed tables and three convenience views; the smoke test proves it cannot update or read contacts.
  • The schema text the model reads is generated from the same spec as the DDL, per dialect, with the plain-English notes that steer it: how "late" is defined, where prices live, what a backorder is.
  • Case 1 sends the schema and never a row. Case 2 sends the customer's message and form values. The dataset tags what is personal so the app can mask it.

Reproduce

Same inputs, identical bytes

The generator is code with a fixed seed; no language model runs when the data is made. Regenerating on another day moves "today" and keeps the story: the outage is always the second full week of last month, the pallet always arrived on a Tuesday.

git clone https://github.com/ugur-vaadin/ai-dataset-generator.git && cd ai-dataset-generator
python3 -m dsgen nordic_supply check --pg --h2-file      # ~10 s + Docker; then read out/nordic_supply/FACTS.md

All companies, brands, carriers, people, addresses and domains are fictional, checked against a denylist of real Nordic and outdoor companies on every run and listed in REVIEW.md for a human pass. Prices in EUR. Figures on this page are from the generation of 7 September 2026, seed 20260907, and are listed in out/nordic_supply/FACTS.md.
